# Rust 起動プログラムの実行

`::rv64::firmware-machine` は、起動 ELF を格納した ROM をフェッチし、レジスタとデータメモリを更新する。現在の起動プログラムが使う ADDI、SLLI、LUI、SD、JAL、AUIPC、BEQ、BNE、BGEU、JALR、LD、XOR、SLTU、MUL を扱う。リセット時に起動アドレス `0x10000` から実行を始める。

## 命令の完了と書き込み

レジスタファイルは1ポートを2つのオペランドの読み出しと書き戻しに使う。命令を開始してから113 tick 以内に両オペランドを取り込む。展開したフェッチの最大経路は24段、受理と書き込み先を決める組み合わせ回路の最大経路は505段である。メモリの読み出しと選択信号が確定する時間も取り、命令を開始してから1024 tick 後に実行結果を使う。乗算は初期化後に518 tick 間隔で更新し、64回目の更新で完了する。[MUL の回路と証明](multiply.md)

`commit` が立つフレームでは命令の PC オフセットと、レジスタ・メモリへの書き込み要求が出る。PC は次の tick、書き込み先が `x0` 以外のレジスタは8 tick 後、ストア先の RAM は16 tick 後に更新される。フェッチ先が無効、命令が未対応、またはアクセスがメモリの規則に合わない場合は `stopped` が立ち、命令の完了と書き込みは発生しない。

## 結果領域の観測

LD または SD を処理している間は、その命令がメモリのデータポートを使う。他の命令では観測用のアドレスを選ぶ。`memory-address` は現在選んでいるアドレスを示し、`probe-data` にはメモリの読み出し遅延がある。観測するときはアドレスを保持し、選択後のアドレスが確定してから32 tick 待つ。[メモリの読み出し規則](firmware-memory.md#ram-の更新と読み出し)

`firmware.toml` の `::rv64::firmware-demo` は、プログラムが積と終了状態を RAM に書くのを待ち、読み出した2語を出力に保持する。同梱イメージでは、82,894 tick で `finished` が立つ。プログラム終了後の JAL 自己ループは引き続き動作する。

## 検証の範囲

結合テストは実際の ROM から実行し、BSS の初期化ループ、LD、MUL、Rust からの復帰と、結果領域の値を確認する。

```sh
host=$(rustc +1.99.1 -vV | sed -n 's/^host: //p')
cargo +1.99.1 test --release --locked --manifest-path verification/Cargo.toml \
  --target "$host" --target-dir target/verification --test firmware_machine
```

`firmware-dispatch` の検証では、任意の命令語、PC、レジスタ値、フェッチの成否、メモリの読み出し値と乗算の結果を与える。受理条件、次の PC、レジスタと RAM への更新要求、書き込む値を参照仕様と照合する。無効な入力では PC オフセットを保持し、両方の更新要求を抑止することも検証する。実際に更新する tick の検証は CPU の結合テストで行う。[組み合わせ回路と乗算の検証手順](../README.md#起動回路の部品を検証する)

命令完了から状態更新までを含む CPU 全体の形式証明、RV64IM の残りの命令、NCG2 Core のセルフホストは今後の作業である。
