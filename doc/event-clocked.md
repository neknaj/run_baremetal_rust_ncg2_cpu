# 変化した配線から順序回路を実行する

セルフホストの検証ツールは、Core が階層展開した NOR、ラッチ、RAM の配線を読み取って `EventVm` を構築できる。構築時に配線を所有し、Core の VM と同じ順序で公開出力と RAM の確定内容を返す。入力は tick ごとに与える。

## 更新する素子の選び方

reset では内部状態、RAM、外部入力を0に戻し、初回の候補に全素子を入れる。公開出力は定数配線も含めて reset 後の値を返す。

1. 外部入力の変化から、その tick に評価する素子を追加する。外部入力を直接読む出力はこの時点で更新する。
2. 候補の NOR、ラッチ、RAM は同じ旧状態から次の値を求める。旧状態を読み終えるまで、素子の出力や RAM の内容を書き換えない。
3. 変化した値を確定し、その配線を読む素子を次の tick の候補に入れる。RAM が語を書き換えた場合は、その RAM 自身も次の候補に入れる。同じアドレスとデータを保持していても、次の tick では更新済みの語を読み出すためである。

変化した配線を読む公開出力だけを更新する。候補、確定前の変更、公開出力を置く領域は構築時に確保する。固定入力で候補が空なら、前の tick で確定した出力を返す。

## 参照仕様と一致する理由

候補にない素子は、その tick に仕様どおり評価しても変化しないことを不変条件とする。初回は全素子が候補にあるため、この条件を満たす。

ある素子の入力配線が変われば、外部入力なら同じ tick、状態素子や NOR の出力なら次の tick で候補になる。候補にない NOR は前の評価と同じ入力から同じ出力を得る。同じ許可とデータを受け取るラッチには、前の tick の保持または代入を繰り返しても変化がない。RAM ではアドレスが変わらず書き換えもなければ、同じ語を登録し、同じ内容を保つ。書き換えがあった RAM は次の候補に入るため、古い読み出し値が残らない。したがって候補の評価と確定は、全素子を毎 tick 評価した結果と同じになる。公開出力は確定した状態とその tick の入力から求める。[NCG2 の tick と状態素子](https://neknaj.github.io/circuitgame2/docs/simulation.html)

## 実装の検証範囲

外部入力や登録出力の変化を処理する `EventVm` は、逆引き表にある依存素子の一覧を `EvaluationQueue::insert_all` に渡す。書き換えた RAM は `insert` で再登録する。通常の Rust ビルドも、Verus が検査するキューの実装を使う。

キューは登録ビットと候補一覧が同じ素子集合を表し、一覧に重複がないことを保証する。一括登録後の集合は、登録前の集合に範囲内の入力候補を加えた集合に等しい。`pop` は登録した末尾の素子を一つだけ除き、reset は全素子を登録する。この契約により、表から渡した全素子が再評価の候補に入る。

逆引き表の構築も Verus で検証する。各行は、その配線を読む NOR・ラッチ・RAM と公開出力の添字を過不足なく一度ずつ含む。対象は、実行時の読み出しにも使う配線添字である。NOR の両入力、状態素子の許可とデータ、RAM のアドレス、公開出力の入力を含む。定数配線には逆引き行を作らない。

NOR の入力は、値の列の添字に変換し、参照する値の列と同じ型に保持する。外部入力・状態素子の出力・NOR の出力には元の配線番号を使う。定数はその後ろの2か所から読み、構築と reset で false と true を維持する。配線の更新では値の列の配線用区間だけを書き換える。

`EventVm` は正規化済みの同じ入力列を逆引き表と NOR 入力表の構築に渡す。Verus は、渡した入力列からゲート順と左右の参照を保って変換することを保証する。型の不変条件は定数の位置とすべての入力添字の範囲を保証する。`PackedNorInputs::next` は自身が保持する値を読み、元の2入力を読んだ NOR と同じ値を返す。

Core の配線を実行器の添字に変換する処理、評価対象外の素子が状態を保つこと、確定後の状態が Core の tick 契約と一致することは、形式検証の対象として残る。小回路の公開フレームと RAM の全記憶内容は Core の標準 VM と比較する。小型の起動 ELF と UART ブートの結合試験では各 tick の公開フレームと最終 RAM を比較する。

## NOR 入力の読み出しの計測

旧実装は各入力を配線番号か定数かに分けて読んでいた。添字で読む最初の実装と比べるため、小型の UART ブート試験で使う波形を Windows の release ビルドに再生した。全38,475 tick の公開出力と最終 RAM が両者で一致し、評価数はどちらも32,070,749件だった。

2回ずつウォームアップしたあと、旧版先行と新版先行を交互にして12組を測った。経過時間の中央値は1,162 msから961 ms、実行スレッドの CPU 時間は1,109 msから953 msになった。対応する各組の新版と旧版の比の中央値は、経過時間が0.833、CPU 時間が0.809だった。先行する試作では、経過時間の比の中央値は0.947と0.955だった。計測の幅があるため、速度の結果はこの回路と実行環境に限る。

添字表と値を同じ型に移したときも、同じ入力で全出力、RAM、評価件数を照合した。変更前の添字版との12組の比較では、ベンチマークを1つの論理 CPU に固定した場合の時間比の中央値は、経過時間が0.920、スレッドの CPU 時間が0.896だった。CPU を固定しない先行試作では CPU 時間の比が1.080で、型の変更による時間差は計測条件によって変動した。

## UART 転送の先頭区間を計測する

[セルフホスト用の転送データ](selfhost.md)がある場合は、全量検証とは別に転送の先頭区間を計測できる。ヘッダーは元の転送語数を保持する。指定した語まで同じ UART 波形で転送し、各語の ACK と RAM の内容を確認して終了する。

```sh
host=$(rustc +1.99.1 -vV | sed -n 's/^host: //p')
cargo +1.99.1 run --locked --release --manifest-path verification/Cargo.toml \
  --target "$host" --example verify_uart_selfhost -- uart-boot.toml \
  selfhost/target/compile-uart.bin --measure-transfer 16
```

出力は回路の構築時間と転送・照合時間を示す。UART 波形の送信中と ACK の待ち時間について、tick 数、評価した素子数、退役信号が有効だった tick 数を表示する。遅延鎖の調査では、先頭から末尾まで伝わる途中に分岐も公開出力もない常時有効な1ビットラッチ列を数える。

33,778語の転送データを使った Windows の release ビルドでは、ヘッダーと先頭16語の転送・照合が7.367秒だった。ACK 待ちは138,841 tickで、このうち74,595 tickでは候補の遅延鎖以外を評価しなかった。ACK 待ちの122,166,437件の評価のうち遅延鎖内は336,372件で、退役信号は138 tickで有効だった。

### 同じ回路の NOR をワードにまとめる候補

同じ tick のゲートは更新前の配線値を読む。左右の入力をそれぞれ `u64` に詰めれば、ビットごとに異なる NOR を1回の `!(left | right)` で評価できる。候補群の幅に対応するビットだけを使い、再評価が必要なビットだけを更新する。変更ビットのマスクは更新前後の XOR で得る。

`--measure-transfer` は宣言順をまたいで連続した入力を探す。`--measure-transfer-shared` は共通の配線を読むゲートを優先して集める。共通入力で集めた群はもう一方の入力をワード内の対応するビットにそろえてから評価する。

| 分け方 | 候補の NOR | 同じ先頭区間で候補に入った評価 |
|---|---:|---:|
| 連続した入力 | 3,286 / 72,720 | 115,216 / 153,450,243 |
| 共通入力 | 18,651 / 72,720 | 27,009,652 / 153,450,243 |

共通入力で集めると、同じ tick に同じ群で4ゲート以上を評価した回数は計1,328,153回だった。この計測は元の評価器の候補を数える。ワード化した評価器の所要時間は配線を詰める処理と出力を確定する処理を含めて測る。

## 検証コマンド

```sh
host=$(rustc +1.99.1 -vV | sed -n 's/^host: //p')
CARGO_BUILD_TARGET="$host" cargo +1.99.1 verus focus --locked \
  --manifest-path verification/Cargo.toml -p ncg2-event-queue -- --no-cheating
cargo +1.99.1 test --locked --release --manifest-path verification/Cargo.toml \
  --target "$host" --test event_clocked --test firmware_machine --test uart_system
```
