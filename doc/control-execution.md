# PC 相対の命令と条件分岐

`::rv64::execute-control` は命令語、起動アドレス `0x10000` からの PC のバイトオフセット、読み出し済みの `rs1`・`rs2` を受け取る。アドレスとレジスタ値の演算は64ビットで桁あふれを捨てる。

| 命令 | 分岐・書き込み |
| --- | --- |
| AUIPC | 絶対 PC に U 即値を加え、`rd` へ書く。PC は4バイト進む |
| BEQ | `rs1 == rs2` のとき符号拡張された B 即値を PC に加える |
| BNE | `rs1 != rs2` のとき符号拡張された B 即値を PC に加える |
| BGEU | 符号なしの `rs1 >= rs2` のとき符号拡張された B 即値を PC に加える |
| JALR | `rs1 + imm-i` のビット0を消して絶対アドレスを作り、起動アドレスを差し引いて次の PC オフセットを求める。現在の絶対 PC に4を加えた値を `rd` へ書く |

条件分岐が成立しなければ4バイト進む。圧縮命令のない構成なので、JALR と成立した分岐の飛び先には4バイト境界を要求する。命令が対象の符号化なら `recognized`、PC やレジスタに結果を適用できるなら `valid` が立つ。無効なら PC を保持してレジスタ書き込みを抑止する。レジスタの番号と値は `register-write` が立つときに使う。`x0` の抑止と飛び先の命令が読めることの検査は、レジスタファイルとフェッチの責務である。

## 検証

起動回路と同じ手順で `execute-control` を検証する。[README の検証手順](../README.md#起動回路の部品を検証する)

展開済み NOR 回路の `recognized`、`valid`、次の PC、書き込み許可を、全入力でビットベクトル仕様と比較する。書き込み許可が立つ入力では、レジスタの番号と値も比較する。検証対象は固定入力に対する組み合わせ結果である。レジスタファイル、命令メモリ、ゲートの伝搬を含む tick 間の更新は別の契約で扱う。
